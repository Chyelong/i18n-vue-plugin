#### 3B: 修复 script 中裸 $t() bug [经验#2]

**Bug 定位**：`processScriptContent` 第 446-448 行的启发式逻辑有误：

```javascript

**问题**：当行含 `this.`（Vue methods/computed 中极常见），生成裸 `$t('xxx')` — 在 script 上下文中 `$t` 未定义。
例：`this.title = '中文'` → `this.title = $t('中文')` ❌ 应为 `this.title = window.$t('中文')`

- [ ] **Step 3:** 将第 446-448 行替换为：

```javascript

// template 区域的 $t() 由 processTemplate 方法处理（不经过此函数）
const prefix = 'window.';
```

删除 `useWindow` 变量。同步更新 `processTemplateString` 方法（第 492 行 `useWindow` 参数），script 调用时始终传 `true`。

- [ ] **Step 3:** 新增裸 $t() 检测 [经验#2]

```javascript
// 扫描 .vue 文件 <script> 区域中的裸 $t()（缺少 window. 前缀）
// 排除 template 区域（template 中 $t() 无需 window.）
function detectBareT(filePath, content) {
  const scriptMatch = content.match(/<script[^>]*>([\s\S]*?)<\/script>/);
  if (!scriptMatch) return [];
  const scriptContent = scriptMatch[1];
  const issues = [];
  scriptContent.split('\n').forEach((line, idx) => {
    // 匹配不带 window. 的 $t( ，排除 this.$t 和注释
    if (/(?<!window\.)(?<!this\.)\$t\s*\(/.test(line) && !line.trim().startsWith('//') && !line.includes('window.$t')) {
      issues.push({ line: idx + 1, content: line.trim(), severity: '🟠' });
    }
  });
  return issues;
}
```

| 13 | filter 硬编码中文 vs 已翻译 name | `items.filter(it => it.name != "地热")` 但 name 已被 $t 翻译 | 比较永远不等 | 用英文标识符字段（description）替代 |
| 14 | UI 状态变量比较不一致 | `checkCodeBtn = $t("发送验证码")` 但 `!= "发送验证码"` | 赋值翻译了但比较用原始中文 | 用布尔标志 isSending 替代文本比较 |
| 15 | 翻译映射变量用于比较 | `status_trs = $t("未处理")` + `if(status_trs == "未处理")` | 翻译后比较失败 | 用原始 status 数值判断 |
| 16 | res.msg 后端响应用于 indexOf | `res.msg.indexOf($t("成功"))` | 后端消息是中文，翻译后匹配失败 | 用 res.code 数值判断 |
| 17 | sort_label 后端字典截取比较 | `sort_label == $t("时")` | 后端返回的截取值是中文 | 保持原始中文比较 |
| 18 | 常量数组元素用于 indexOf | `const TYPES = [$t("故障1"), ...]` + `TYPES.indexOf(backendValue)` | 数组翻译后无法匹配后端值 | 保持原始中文 |
```

#### 6B: 修正双重翻译判断标准 [经验#8]

- [ ] **Step 2:** 在注意事项中添加：

```markdown
### 双重翻译判断标准（避免误判）

审核时需正确区分以下三种模式：

| 模式 | 判断 | 说明 |
|------|------|------|
| `$t("中文字面量")` | ✅ 安全 | 翻译字面量 key |
| `$t(变量)` 且变量值为中文 | ✅ 安全 | 变量是翻译 key，模板处是唯一翻译层 |
| `$t($t("中文"))` | ❌ 双重翻译 | 两层 $t 嵌套 |
| JS 中 `$t("中文")` + 模板中 `$t(变量)` | ❌ 仅当变量 = JS 中 $t 的返回值 | JS 已翻译 + 模板再翻译 |

**常见误判**：子代理将 "JS 中保持中文原值 + 模板中 $t(变量)" 误判为双重翻译。这是正确的 i18n 模式——JS 持有 key，模板翻译。
```

## $img 图片国际化注意事项

### webpack require() + hash 不兼容

Vue 项目中 `<img :src="$img(require('../assets/bg.png'))">` **无法工作**：
- `require()` 经 webpack 处理后路径变为 `/static/img/bg.a1b2c3d4.png`（带 hash）
- `$img` 拼接 `_tw` 后缀 → `/static/img/bg.a1b2c3d4_tw.png` → 文件不存在

**正确做法**：把多语言图片放到 `static/` 目录（不经 webpack 处理），用绝对路径：
```html
<img :src="$img('/static/img/bg.png')" />
```

### $img 与 $imgVar 路径基准不同

| 函数 | 路径基准 | 示例 |
|------|---------|------|
| `$img(path)` | 相对于 HTML 页面 | `$img('img/nav/01.png')` |
| `$imgVar(name, path)` | 相对于 CSS 文件 | `$imgVar('--nav', '../img/nav/01.png')` |
```

## initI18n 异步加载 + 首屏翻译方案

当 initI18n 在 mounted 中调用（非模块顶层）且语言由后端接口返回时：

1. data() 中的 $t() 因翻译数据未加载而返回原文
2. 模板首次渲染时翻译同样为空
3. $t 非 Vue 响应式，数据加载后不自动重渲染

**解决方案（langKey 强制重建）：**

```javascript
new Vue({
  data: { langKey: 0 },
  template: '<App :key="langKey"/>',
  mounted: async function() {
    // 同步获取语言设置
    $.ajax({ url: '/index/info', async: false, success(res) {
      window.$language = res.data.language || 'zh';
    }});
    await initI18n(window.$language);
    this.langKey++; // key 变化 → 整棵组件树销毁重建
  }
});
```

**适用场景**：
- initI18n 在 mounted 中调用（非模块顶层同步执行）
- 语言由后端接口返回（需 AJAX 获取）
- i18n/index.js 使用 `await import()` 动态加载语言包

**考虑改进（可选）**：init 脚本导出 `i18nReady` Promise，简化应用层集成：
```javascript
// i18n/index.js 导出
export const i18nReady = initI18n(detectedLang);
// 应用层使用
import { i18nReady } from './i18n';
i18nReady.then(() => { /* 翻译已就绪 */ });
```
此为可选增强，不在 v2.3.0 必做范围内，记录供后续版本参考。
```

## 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| 裸 $t() 检测正则误报 `this.$t` | 排除 `this.$t`、`window.$t`、注释行；`--fix` 模式同样排除 |
| 第三方排除误跳用户自己的 lib/ 目录 | 仅排除目录名精确匹配 `vendor`/`lib`/`third-party`，不做 glob 模式 |
| Vue 2 buble 引号修复（line 219）可能影响非 buble 项目 | 单引号包裹在所有 JS 引擎中等效于双引号，无兼容性问题 |
| 数据映射字典检测误命中 UI 配置 | **已降级为仅警告**（不跳过替换），用户在步骤 3.5 人工确认 |
| script 中始终 window.$t() 可能与 `this.$t` 习惯不符 | Vue.prototype.$t 挂载后 `this.$t` 可用；window.$t 在所有上下文中都可用，更安全 |
| 状态文件在多人协作时冲突 | 加入 .gitignore |
| `--fix` 模式自动修改代码的风险 | 仅修复裸 $t() 这一类确定性问题；高危模式不自动修复 |
| 全项目审核耗时较长 | 验证脚本直接扫描文件，不依赖 AI，秒级完成 |
